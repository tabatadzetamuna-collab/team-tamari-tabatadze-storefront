## Decision
კალათის ყველა სტეპერი და წაშლის ღილაკი ითიშება, სანამ კალათის რომელიმე მოთხოვნა მიმდინარეობს. კალათის ყველა mutation (add, update, remove) ერთ TanStack Query scope-შია (`scope: { id: 'cart' }`), ამიტომ მოთხოვნები რიგში დგება და მიყოლებით სრულდება.

## Consequences
- პასუხები არასწორი თანმიმდევრობით ვერ მოვა — არც ერთ ხაზზე, არც სხვადასხვა ხაზს შორის.
- ეკრანზე ყოველთვის სერვერის პასუხია (qty, lineTotal, subtotal) — ფრონტზე არაფერს ვითვლით.
- მოთხოვნის დროს მთელი კალათის ღილაკები წამით ითიშება — უფრო „უხეშია", ვიდრე თითო ხაზის გათიშვა, მაგრამ შეცდომას ვერ იძლევა.
- debounce უფრო სწრაფად იგრძნობოდა, მაგრამ მეტი კოდი და დროებითი მდგომარეობა დასჭირდებოდა.
